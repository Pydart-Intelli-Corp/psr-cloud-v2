PSR CLOUD V2 - MACHINE API ENDPOINTS REFERENCE
==============================================

BASE URL: http://localhost:5000
All endpoints support both GET and POST methods with InputString parameter unless specified otherwise.

==============================================

==============================================

1. CLOUD TEST
   Endpoint: /api/Machine/CloudTest
   Methods: GET, POST
   Description: Test machine connectivity to cloud
   Example: http://localhost:5000/api/Machine/CloudTest
   Response: "Cloud test OK"

   Response: "Sales details saved successfully."

5. SAVE MACHINE STATISTICS
   Endpoint: /api/MachineStatistics/SaveMachineStatisticsFromMachine
   Methods: GET, POST
   Description: Save machine statistics (tests, cleaning, gain, auto-channel)
   Example: http://localhost:5000/api/MachineStatistics/SaveMachineStatisticsFromMachine?InputString=S1|LSE-SVPWTBQ-12AH|LE3.36|MM15|T450|D6|W6|S80|G6|DISABLE|D2026-12-27_09:00:00
   Format: SocietyId|MachineType|Version|MachineId|T{tests}|D{daily}|W{weekly}|S{skip}|G{gain}|ENABLE/DISABLE|D{date_time}
   Response: "Machine statistics saved successfully."

6. CHECK MACHINE UPDATES
   Endpoint: /api/MachineNewupdate/FromMachine
   Methods: GET, POST
   Description: Check for pending firmware/software updates (password, rate chart, correction)
   Example: http://localhost:5000/api/MachineNewupdate/FromMachine?InputString=s1|LSE-SVPWTBQ-12AH|LE3.36|Mm15|D2025-11-12_10:59:09
   Format: SocietyId|MachineType|Version|MachineId|D{date_time}
   Response: "DD-MM-YYYY HH:MM:SS AM/PM|Status"
   Status Values:
     - "No update" - No pending updates
     - "password" - Password update available (StatusU=true or StatusS=true)
     - "chart" - Rate chart update available (status="active" and machine in MachineIds)
     - "correction" - Correction update available (status=1 in machine_corrections table)
     - "password,chart,correction" - Multiple updates available (comma-separated)
   Example Response: "30-01-2026 03:58:49 PM|password,chart,correction"
   Notes:
     - Uses foreign keys (machine.Id, society.Id) for database operations
     - Case-insensitive society lookup (s1, S1, etc.)
     - Machine ID normalized (Mm15 -> M15) before lookup
     - Always returns HTTP 200 with quoted string response

IMPLEMENTATION NOTES
==============================================

SOCIETY ID FORMAT:
- Accept: S1, S2, S3 (without dash)
- No longer support: S-1, S-2 format

MACHINE ID FORMATS:
- API accepts: M12, Mm12, MM12 (string identifiers)
- Normalizes to: 12 for database lookups
- Database stores: Foreign key (machine.Id integer)
- Returns: M12 in API responses

DATA ISOLATION:
- All GET endpoints require societyId parameter
- All queries filter by society.Id for data isolation
- Machine lookups verify machine belongs to specified society
- Foreign keys (machine.Id, society.Id) used for all database operations

RATE CHART STORAGE:
- Stores machine database IDs (foreign keys) internally
- Converts to machine identifiers (M12, M13) in responses
- Supports multiple machines per rate chart entry

ESP32 COMPATIBILITY:
- All InputString endpoints support GET and POST
- Always returns HTTP 200 with error messages in content
- Quoted string responses for text data
- Pipe-delimited format for structured data

PAGINATION:
- GetLatestPriceChart: 10 records per page
- Machine statistics: Last 100 records by default
- Configurable limits via query parameters
